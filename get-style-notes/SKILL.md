# get-style-notes：得到 GET 笔记风格的阅读笔记

把一篇内容变成"读完像编辑替你转述过"的中文笔记。核心不是压缩字数，而是**转述**：结构清晰、证据保真、说人话。

## 输入与获取

输入可能是 URL、粘贴的长文本、本地文件（md/txt/docx/pdf）。

URL 按环境可用性依次尝试，取第一个能拿到完整正文的：

1. defuddle CLI：`defuddle parse <url> --md`（正文最干净）
2. 环境内置的网页抓取（WebFetch / web reader 等）
3. Jina Reader：`https://r.jina.ai/<url>`
4. `curl -sL <url>`

抓不到正文（付费墙、纯 JS 渲染、登录墙）就如实告知并停止，不用残缺内容生成笔记。

## 笔记模板

生成单个 Markdown 文件，结构固定：

```markdown
# {{文章标题}}

> 来源：{{URL 或出处}} · {{作者/机构}} · {{发布日期，可考才写}} · 原文约 {{字数}} 字

## 一句话总结
{{不超过 60 字，直接说这篇讲了什么、结论是什么。}}

## 核心观点
1. **{{观点短语，8 字以内小标题}}**：{{2-4 句转述。观点后必须跟原文的证据：数据、案例、引证。}}
2. ...

（3-5 条为宜；超过 5 条说明主次没分清，合并同类项。）

## 金句摘录
> {{原文原话，一字不改}}

（1-3 句真正值得记住的；没有就整节省略，不硬凑。）

## 概念卡片
- **{{术语}}**：{{一句大白话解释}}

（只收原文关键术语；没有就整节省略。）

## 值得记住
- {{这条内容给我的启发或可执行的动作}}

（可选，1-3 条；必须由原文内容自然引出，不写空泛感悟。）
```

## 风格红线（验收标准）

- **不编造**：所有观点、数字、人名、机构名必须来自原文并原样保留，拿不准的不写。
- **转述，不是摘要腔**：像把文章讲给同事听。禁止"本文""综上""在当今快速发展的时代""值得一提的是"这类论文腔和 AI 腔。
- **证据密度**：每条观点后面要有支撑，只有论点没有论据的条目不合格。
- **中文表达**：中文标点，短句为主，术语首次出现给解释。
- **金句必须原文**：引用不许改写；改写过的句子不能进金句节。

## 保存

默认写入当前工作目录 `notes/` 下，文件名 `YYYY-MM-DD-{{标题短横线}}.md`，交付时给出文件路径和一句话内容概述。用户指定 Obsidian 库或其他位置时按指定执行。

写完自检再交付：一句话总结是否直接给结论？每条观点是否有证据？有没有任何原文里不存在的信息？三项全过才交付。
